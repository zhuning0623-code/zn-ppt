# 交付检查

只在私有构建目录保存检查记录，交付稿里不出现检查日志。以下每项都要有来自成品的观察或工具结果，不能只填“已完成”。

| 要求 | 检查方式 | 不通过时处理 |
| --- | --- | --- |
| 概括与补充 | 已先展示实质内容概括，并结合主题询问扩展角度、细节和实际材料；用户已明确跳过时记录其要求 | 补齐沟通环节，已确认方案不重复询问 |
| 内容具体 | 阅读逐页实际正文，指出核心信息和支撑；检查重复论述与只有标签的页面 | 补充机制、例子、证据或执行细节；合并没有新信息的页 |
| 背景层次 | 多数正文背景有主题相关层次，文字阅读区清楚；未以几乎不可见纹理敷衍 | 重做背景与图文关系，保留必要的安静页面 |
| 视觉有变化 | 实际看整套缩略图和代表页；指出内容驱动的构图差异 | 重排重复骨架；避免仅换颜色和装饰 |
| 内容饱满且可读 | 看正文是否长期只有几句短语和大片无目的空白，同时检查字号与层级 | 先补内容或重组，不用放大标题、塞装饰或缩字号补救 |
| 已使用 ImageGen | 查实际工具调用结果、已保存素材与最终使用页；检查 PPTX 图片对象 | 工具可用时真实生成并嵌入，修复路径与裁切 |
| 保留编辑能力 | 检查文字/表格/图表/示意对象结构；应用可用时修改代表对象 | 将应编辑的内容恢复为原生对象；明确位图内部不可逐项编辑 |
| 转场实际存在 | 检查最终 PPTX 非封面页的 transition 与原计划对应 | 用工具写入并重查，不能只在最终文字中列出效果 |
| 页内动画存在 | 检查 timing、目标对象和点击步骤；与讲述计划对应 | 添加有意义的分步出现，避免错误目标或覆盖已有动画 |
| 实播体验 | 有目标应用时进入放映，观察效果及点击顺序 | 修复；无法实播时准确标明检查范围 |

标准完整新稿可运行 `pptx_motion.py inspect` 并启用 `--require-images --require-transitions --require-reveals`。统计不判断设计质量：字符多不等于内容好、有图片不等于用过生图、有 XML 节点不等于实播验证。

检查结束后记录仍未满足的要求。具备修复条件就继续完成；工具或环境限制导致无法实现时，如实说明，不把少了生图和动态效果的稿件称作完全满足需求。
